## Устройство

**Файлы.**
- `history.js` (корень сайта, ES-модуль без зависимостей) — формат, проверки и чтение; общий для сайта, исследований и ночной задачи.
- `scripts/history-job.js` — логика ночной задачи без Node-API: работает и в Node, и в превью (для сухого прогона с хранилищем в памяти).
- `scripts/history-sync.mjs` — обёртка для Node: подпись S3 (SigV4) для R2, запуск `history-job.js`.
- `.github/workflows/history.yml` — cron каждую ночь + `workflow_dispatch` + пуш в файлы задачи.

**Хранилище** (ключи в бакете):
- `v1/<tf>/<SYM>/<YYYY-MM>.json.gz` — свечи монеты за месяц (UTC), gzip-JSON по столбцам: `{v, s, tf, m, p, t, o, h, l, c, vo, q}`; `t` — смещения от начала месяца в свечах, `p` — время последней свечи предыдущего месяца, как его видела задача (для проверки стыка). Числа — как `+строка` Binance: JSON-число восстанавливается побитно.
- `v1/1d/<YYYY-MM>.json.gz` — дневные свечи всех USDT-пар тикера за месяц, одним файлом (для `pools()` и снятых монет), тот же формат по монетам.
- `index.json` — `{v, from, updated, tfs, s: {SYM: {tf: [первый месяц, последний месяц, время последней закрытой свечи, пустые месяцы?]}}, d: {…дневные…}}`.
- `status.json` — итог последнего прогона (хост Binance, сколько записано, ошибки): журнал Actions без входа не читается.

**Монеты.** Логика `pools()` из `stage05.js`: каждая USDT-пара, хоть раз бывшая в дневном топ-75 по обороту за последние 3 года, снятые остаются, плюс `MAJORS`, без стейблов (`M.STABLE`). Расчёт топа — одна общая функция в `history.js`, ею же пользуется `stage05.pools()`. Однажды сохранённая монета не убирается.

**Таймфреймы.** 1h и 4h; 15m — только если после первого прогона хранилище намного меньше 10 ГБ (оценка ~1.5–2 ГБ на 15m).

**Ночью** пишется только текущий месяц (и прошлый — один раз, в первую ночь нового месяца); прошлые месяцы не меняются. Файл без новых свечей не переписывается. Индекс — последним, после файлов. Записей класса A: первичная загрузка ~40–60 тыс., дальше ~1.5 тыс. за ночь (~45 тыс. в месяц) при лимите 1 млн.

**Binance.** Сначала `data-api.binance.vision` (раннеры GitHub в США, `api.binance.com` оттуда закрыт). Архивы `data.binance.vision` — только с согласия владельца.

**Чтение** (`history.js` `candles(sym, tf, start, end, {api})`):
1. `index.json` (без кэша браузера, в памяти 5 мин).
2. Месяцы из R2 (до 16 запросов сразу), хвост после последней сохранённой свечи — с Binance через переданную функцию старого пути.
3. Проверки: формат и версия, монета/ТФ/месяц файла, время по сетке ТФ и внутри месяца, строго по возрастанию, без дублей и разрывов на стыке месяцев (кроме разрыва, который задача видела у Binance — `p`), только закрытые свечи. Любая ошибка — весь отрезок старым путём с Binance.
4. Кэш IndexedDB (`sigma-history`): сжатые байты файла; прошлые месяцы — навсегда, последний месяц серии — пока его последняя свеча совпадает с индексом. Потолок размера, вытеснение давно не читанных. Каждое обращение к хранилищу — в try/catch (Safari может стереть данные).
5. Кнопка «Очистить кэш истории» в бэктесте.

**Сайт.** `fetchHistory` берёт свечи через `candles()` и переводит в свой формат строки (`k[6]` = время закрытия). Ограничение ~3 млн свечей в прогоне остаётся. Оценка времени первого запуска учитывает сохранённую историю.

**Исследования.** `stage05.klines()` → `candles()`; `pools()` берёт дневной оборот из R2, если он покрывает период, иначе старым путём. `smc_check.js` и `fib.js` ускоряются сами.
