# Грабли и как их обошли

Что ломалось при разработке Sigma Radar, почему и как это исправили. Подробности в сообщениях коммитов (хэш в скобках).
Перед большой правкой стоит пробежать глазами этот файл: многие ошибки повторяются в новом виде.

## Сервер: Edge Function `bot`, коллектор на Railway

| Проблема | Причина | Решение |
|---|---|---|
| Прогон бота шёл ~40 с, личные боты не успевали | ~600 мелких запросов к Binance, по 10 одновременно | 25 запросов одновременно: 40 → 17 с (94d1a80) |
| Бот падал из‑за нехватки памяти и CPU | свечи хранились строками Binance (12 строк на бар), анализ одной монеты считался заново для каждого бота | компактные числа, один анализ на монету и настройки канала для всех ботов (2636981) |
| Кэш свечей в памяти функции не давал экономии | Supabase **запускает функцию заново на каждый вызов** (boot → прогон → shutdown), кэш живёт один прогон | свечи держит коллектор на Railway (`POST /scan`), бот берёт всё одним запросом (10002d2, 626f457) |
| Коллектор не подогревал свечи, на которых торгуют | запрос сигналов перезаписывал `s.lazy` поверх торговых | отдельная метка `tradeAt` (13ba6c6) |
| Бот мог взять анализ, посчитанный по другим правилам | коллектор грузит math.js с сайта, сайт и функция обновляются не одновременно | `M.fingerprint()`: анализам коллектора бот верит только при совпадении отпечатка, остальное считает сам (626f457) |
| Минута терялась целиком из‑за 418 от Binance | общий исходящий адрес Supabase, один отказ на тикер за 24 ч | тикер хранится и переиспользуется до 15 мин; оповещение только после 3 отказов подряд (4dd9065) |
| Торговля пропускала минуты, когда сканы уведомлений съедали бюджет | сигналы считались до торговли | сначала торговля всех ботов, сигналы делят остаток (v29) |
| При деплое коллектор терял стакан | `npm start` не передавал SIGTERM в node | запуск `node` напрямую (eb1ad86) |
| Бесконечные пересинхронизации стакана и бан Binance | события, пришедшие во время загрузки снимка, выбрасывались | одна синхронизация на график, снимки с интервалом 1.2 с (c7e0864) |
| Фьючерсный стакан пустел у цены | снимок на 1000 уровней покрывает только ±0.15 %, обновления за его пределами отбрасывались | изменения за пределами снимка сохраняются (6e5d398) |

## Уведомления в Telegram

| Проблема | Причина | Решение |
|---|---|---|
| Первый настоящий сигнал «проглатывался» | пустое состояние считалось первым запуском | пустое состояние ≠ первый запуск (f3a13f9) |
| Сигнал приходил на касание, а подтверждение разворота не приходило никогда | касание запоминалось один раз | одно сообщение на касание, оно редактируется при подтверждении и при входе бота (5756d20) |
| Одна монета приходила 2–3 сообщениями (общие правила, профиль, «Рынок») | независимые потоки | поток «≥ 60» убран, «Рынок» пропускает монеты, о которых уже сказали «Мои сигналы» (5756d20) |
| В Telegram менялись сигналы, когда на сайте просто переключали таймфрейм | «Рынок» брал настройки с открытой страницы | настройки сохраняются явно кнопкой (5756d20) |
| Одно и то же касание повторялось на каждой новой свече (WAL) | ключ = время касания, а цена стоит за границей несколько баров | эпизод: одна монета и сторона в пределах `TOUCH_BARS` свечей = одно сообщение (d552192) |
| Тихие часы «прилипали» к следующему прогону | множество `QUIET` в тёплом экземпляре не очищалось | очищается в начале каждого прогона (d552192) |
| В `money()` ломался формат сумм после деплоя | регулярка содержит буквальный неразрывный пробел, он терялся при копировании | в JSON деплоя писать ` `, после деплоя сравнивать с репозиторием (94d1a80) |

## Бэктест и данные

| Проблема | Причина | Решение |
|---|---|---|
| Результат бэктеста менялся от дня к дню (у друга 200k → 93k), «пропадали» монеты вроде MUBARAK | честный режим брал пул из сегодняшнего топ‑50 × 2.5; за год через топ‑20 проходит ~200 монет, узкий пул выбрасывал большинство, итог зависел от того, кто в топе сегодня | пул не меньше 150 монет (2× топ, до 400): +0.55…0.75R по дням → стабильные ~+0.25R (ece187b) |
| Бэктест на «сегодняшнем топе» завышен | ошибка выжившего: в прошлое переносится состав, известный только сейчас | по умолчанию топ на каждый момент по обороту за 24 ч, как у живого бота (b7bc1d6) |
| Вкладка разрасталась на сотни МБ | история хранилась строками Binance | 7 числовых полей, потолок ~1.5 млн свечей (39ca7b9) |
| В сканер, к ботам и в бэктест попадали золото, обёрнутые монеты и стейблкоин U | не было фильтра | исключены везде (f3a13f9) |
| Объём последней свечи врал | свеча ещё формируется | учёт незакрытой свечи (72fb6c2) |
| Сделки бэктеста и бота могли разойтись при правке уровней | цель и стоп считались в двух местах | `levels()` в math.js, общий для `planEntry` и сигналов; сделки сверены на синтетике: 122 сделки, совпадают (d552192) |

## Окружение разработки

- Локально нет Node, Deno и Python. Синтаксис JS проверяется импортом модуля в превью браузера: ошибка вроде «process is not defined» значит, что файл разобрался.
- Деплой функции: MCP `deploy_edge_function` с полными `index.ts`, `../_shared/math.js`, `../_shared/tg.ts`, `verify_jwt: false`. После деплоя `get_edge_function` и diff с репозиторием.
- Правки больших блоков в index.html делать через Edit или точную замену, которая падает, если блок найден не ровно один раз. `perl -0pi` однажды вставил текст в начало файла.
- В Bash нельзя `sleep` и `rm` после `cd`: ждать через фоновые задачи, временные файлы класть в новую папку.
- Пуш в `main` сразу выкатывает сайт на Vercel, а `server/` выкатывает коллектор на Railway.
