# Грабли и как их обошли

Что ломалось при разработке Sigma Radar, почему и как это исправили. Подробности в сообщениях коммитов (хэш в скобках).

## Коротко перед работой

Ошибки, которые уже повторялись. Читать каждую сессию; таблицы ниже — искать grep'ом по разделу, который трогаешь.

1. Кириллицу и другие не-ASCII символы менять только через Edit. `perl`/`sed`-замены портили весь файл (двойная кодировка) и теряли `\u`. С 09.11 это ловит хук `scripts/check-encoding.sh` (`.claude/settings.json`): после каждой правки или команды он сверяет изменённые файлы с HEAD и сообщает о новой двойной кодировке и битом UTF-8. Ручной запуск — `bash scripts/check-encoding.sh`. В тексте о самой ошибке не ставить закрывающую ёлочку сразу после букв D со штрихом и N с тильдой: хук примет это за порчу (так он сначала поймал собственный комментарий).
2. Функции `bot` и `tg` выкладывает GitHub Actions при пуше в `supabase/functions`.
   - Нужную им миграцию применить **до** пуша.
   - После пуша проверить, что запуск успешен, что номер версии вырос и что в `bot_runs` нет ошибок. Код выкладывается прямо из репозитория, поэтому сверять файлы не нужно.
   - `get_edge_function` для `tg` возвращает ~30 КБ прямо в разговор: без нужды не вызывать.
   - Ручная выкладка через MCP — только запасной путь: все три файла, JSON с экранированными `\uXXXX`.
3. Миграция:
   - сначала прогнать её с проверками в транзакции, которая заканчивается `raise exception` (откат);
   - при смене подписи функции старую удалять в той же миграции, новым параметрам давать значения по умолчанию, права выдавать заново.
4. Порядок выкладки: миграция (обратно совместимая) → функция `bot` → сайт.
5. Правка `math.js`:
   - сохранить прежнюю копию в `tests/_ref/math.js`;
   - пройти `tests/math.html?ref=_ref/math.js`: сделки и отпечаток анализа должны совпасть.
6. После пуша проверить, что Vercel отдаёт новую версию; если нет — выложить вручную с `withLatestCommit` или пустым коммитом (`git commit --allow-empty`, 2.81: через 30 с версия пришла).
7. Превью:
   - скрытая панель останавливает `requestAnimationFrame`;
   - `focus()` и `scrollIntoView` сдвигают координаты для мыши;
   - текст в `::after` не виден в `scrollWidth` — ширину мерить через `canvas.measureText`;
   - затемнённый скриншот — помеха захвата, переснять.
8. Таблицы и формы на телефоне проверять на 320 px: там обрезается то, что влезает на 375.
9. Состояние, которое меняют двое (шаг бота и действие пользователя), защищать блокировкой строки и номером версии, а не надеждой на редкость совпадений.
10. Тексты вида «$10 000», «10 000» и числа из исследований не зашивать: брать из данных или показывать, только пока данные совпадают с проверенными.

Новую SQL-функцию вызывать сразу после выкладки в транзакции с откатом; ошибку сервера показывать её текстом, а не «нет связи» |

| Смена подписи функции в базе ломает вызовы | функция с новым параметром создаётся рядом со старой, и вызов с прежними аргументами становится неоднозначным; у `ub_commit` менялся и тип результата | старую подпись удалять в той же миграции, новым параметрам давать значения по умолчанию, права выдавать заново; сначала прогнать миграцию с проверками в транзакции, которая заканчивается исключением (откат) |
| Railway съел включённые в Hobby $5 к середине цикла и ушёл в перерасход ($8 за 16 дней) | считали только трафик, а Railway берёт поминутно за память и процессор; стаканы шли каждые 100 мс (в 6 раз больше сообщений, чем нужно тепловой карте раз в 10 с), стакан хранился до ±25 %; измерений не было | `/health` → `res`: процессор, память (и cgroup, как считает Railway), разбивка процессора и исходящего трафика по частям, сетевая карта (`net`). Стаканы раз в 1 с (спот) и 500 мс (фьючерсы), стакан до ±15 %, `--max-semi-space-size=4`. Исходящий трафик — это прежде всего **TCP-подтверждения входящих потоков**: по пакету на каждый пакет от Binance (~180 в секунду, ~75 % исходящего, ~$1.6 в месяц), ответы `/scan` — лишь ~250 КБ в минуту. Значит, цена потока растёт с числом сообщений, а не с байтами. Итог 29.10: ~0.11 vCPU, ~334 МБ, ~1 МБ в минуту исходящего ≈ $7.7 в месяц (до правок — ~$15). Перед новой нагрузкой на коллектор (монеты, история, поток) прикидывать цену |
| Запись для исследования внутри прогона бота (2.90, `signal_books`) | сбой лишней записи (биржа, таблица) мог бы уронить минуту торговли, а первая выкладка застаёт уже идущие сигналы | запись — после `bot_commit`, в своём `try`: ошибка только в `bot_runs.error` («стакан сигналов: …»); уникальность (монета, таймфрейм, свеча касания) и `ignoreDuplicates` вместо памяти экземпляра; `at` хранится, чтобы отделить поздние снимки. Без Deno под рукой код записи прогнан в превью на настоящем сигнале и стакане (те же функции `math.js`) до пуша |

## Уведомления в Telegram

| Проблема | Причина | Решение |
|---|---|---|
| Первый настоящий сигнал «проглатывался» | пустое состояние считалось первым запуском | пустое состояние ≠ первый запуск (f3a13f9) |
| Сигнал приходил на касание, а подтверждение разворота не приходило никогда | касание запоминалось один раз | одно сообщение на касание, оно редактируется при подтверждении и при входе бота (5756d20) |
| Одна монета приходила 2–3 сообщениями (общие правила, профиль, «Рынок») | независимые потоки | поток «≥ 60» убран, «Рынок» пропускает монеты, о которых уже сказали «Мои сигналы» (5756d20) |
| В Telegram менялись сигналы, когда на сайте просто переключали таймфрейм | «Рынок» брал настройки с открытой страницы | настройки сохраняются явно кнопкой (5756d20) |
| Одно и то же касание повторялось на каждой новой свече (WAL) | ключ = время касания, а цена стоит за границей несколько баров | эпизод: одна монета и сторона в пределах `TOUCH_BARS` свечей = одно сообщение (d552192) |
| Тихие часы «прилипали» к следующему прогону | множество `QUIET` в тёплом экземпляре не очищалось | очищается в начале каждого прогона (d552192) |
| Сигнал терялся, если Telegram не принял сообщение | эпизод записывался как отправленный сразу, с `mid` 0 | неотправленное помечается `retry` и уходит снова, до трёх прогонов; списки «Ещё сигналы» и «Рынок» — так же (2.37) |
| Одно касание могло прислать ложное «отскок не удержался» | эпизод жил под несколькими ключами одного объекта; в JSON базы они становятся копиями и расходятся | один ключ на эпизод, старые копии удаляются, остаётся самая свежая (2.37) |
| В `money()` ломался формат сумм после деплоя | регулярка содержит буквальный неразрывный пробел, он терялся при копировании | в JSON деплоя писать ` `, после деплоя сравнивать с репозиторием (94d1a80) |
| Сообщение сигнала могло навсегда остаться «ждём подтверждения» | правка (`tgEdit`) не проверяла ответ Telegram, а стадия эпизода менялась в любом случае | `tgEdit` возвращает, прошла ли правка; стадия меняется, только если прошла правка или короткий ответ, иначе до трёх попыток (2.39) |
| Telegram «Рынок» присылал около трети подтверждённых сигналов (на топ-100 1h за двое суток 1 из 3), друг решил, что сигналы идут только при открытом сайте | `marketSignals` проверял разворот по закрытой свече (`tradeRow`), а порог силы — по силе текущей свечи, у которой своё подтверждение ещё не выполнено (−20 баллов) | сила и разворот берутся с закрытой свечи, как в `mySignals` (2.41). Проверено пересчётом его настроек за те двое суток |
| В Telegram человека писали боты, которые не были ботом его профиля (до 2.75; 2.74 закрыл только часть) | сервер не знал, чей бот: связь «профиль → бот» жила на устройствах (`sr_ubot` в `user_state`), Telegram привязывался к любому боту кодом | `user_bots.user_id` (уникальный, каскад) + `ub_mine` / `ub_claim`; Telegram — только `ub_tg` бота профиля в `profiles.tg_id`, проверка `user_bots_tg_needs_profile`; привязка по коду удалена (2.75) |
| Человек заблокировал бота, а бот профиля продолжал слать ему сообщения, сайт показывал «Включено» (до 2.85) | «выключить Telegram» было написано в пяти местах (`ub_tg`, `/stop`, `/unlink`, кнопка «u!», ответ 403), и ответ 403 удалял только подписку | одна SQL-функция `tg_chat_off(chat, unsubscribe)` для всех пяти (2.85). Новое «выключить» — только через неё |
| Брошенный серверный бот работал ещё месяц после вопроса «Удалить прежний бот?» (до 2.85) | `ub_get` и показывает бота, и продлевает ему `last_seen`, а вопрос читал прежний бот, чтобы показать его итог | `ub_get` продлевает только бота своего профиля (2.85). ## Окружение разработки

- Автоматический режим Claude Code не даёт выдавать права в базе (`update profiles set is_owner …`) и применять миграцию, на которую владелец не сказал «да» именно в этом сообщении (даже если «да» было на этап целиком). Права — строкой SQL владельцу в SQL Editor; на каждую миграцию — отдельное «да».
- Проверка входа без Telegram: запрос входа создаётся через функцию `auth`, подтверждается в базе (`update login_requests set tg_id = -1000 …`), токен — через `/auth/v1/verify`; потом удалить пользователя (`op: delete` или `delete from auth.users`) и строки `login_requests`, `tg_subs` с `-1000`. Ответы `json_build_object` идут с пробелами (`"id" : "…"`) — grep по `"id":"` их не находит.

- Страницы за входом (с 2.66) локально: поддельная сессия не годится — сервер отвечает 401, обновление токена падает, и страница выходит из профиля. Вместо этого — второй сервер на 8766 (копия `serve.ps1` во временной папке), который отдаёт `index.html` с заменой `const LOCKED = !AUTH;` → `const LOCKED = false;` на лету; файлы на диске не меняются, конфиг — в `.claude/launch.json` (в `.gitignore`). Экран входа проверять на обычном 8765 (2.68).
- Считать запросы сайта через `performance.getEntriesByType('resource')` можно только после `performance.clearResourceTimings()` и `setResourceTimingBufferSize(5000)`: буфер по умолчанию — 250 записей, скан рынка заполняет его за пару минут, и новые запросы молча не попадают в список (2.89: «стакан не обновляется» оказался полным буфером).
- Узкая панель приложения: пресет `desktop` в `resize_window` даёт её ширину (бывает около 305 px), а не десктоп; для настоящего десктопа — явные 1440×900 (2.68).
- Клик-пути с сервером (бот, Telegram) без боевой базы и без входа: открыть любой файл того же сайта (`/README.md`), подменить `window.fetch` (ответы `rpc/*`, `profiles`, `user_state`; публичные чтения без токена — на настоящий сервер), положить выдуманную `sr_auth` с `exp` на сутки вперёд и записать `index.html` через `document.open(); document.write(html); document.close()` — окно то же, модуль стартует уже с подменой. Порт 8765 может держать сервер другой копии репозитория — проверить `curl` по свежей строке кода (2.75).
- Синхронизация «двух устройств» в одной вкладке (2.82): поддельный сервер `user_state` / `state_put` в переменной окна, хранилище `sr_*` каждого «устройства» — снимком, переключение — снимок, восстановление и `document.write` с `location.reload()` → своей функцией в тексте страницы (настоящая перезагрузка теряет подмену). Перед `document.write` очищать таймеры страницы, кроме своих ожиданий (иначе `await` проверки не вернётся). Скрытая панель: `document.hidden` — `true`. Мусор, записанный проверкой в синхронизируемый ключ (`sr_bot` без `profiles`), ломает старт модуля на всех «устройствах» — проверять своими значениями правильной формы.
- Превью может само открыть правленый `index.html` отдельной вкладкой `file://` и сделать её активной: `javascript_tool` без `tabId` уходит туда («Failed to resolve module specifier '/tests/smoke.js'»). Проверки — с `tabId` вкладки сервера (`tabs_context`) (2.62).
- Локально нет `gh`: чужой публичный репозиторий (например, версии Lovable `Rub1n1337/modern-crypto-screener`) — `git clone --no-checkout` во временную папку и `git show <коммит>:<файл>` (2.60).
- Локально нет Node, Deno и Python. Синтаксис JS проверяется импортом модуля в превью браузера: ошибка вроде «process is not defined» значит, что файл разобрался.
- Код для Node (задача GitHub Actions) писать без Node-API, а обёртку с Node-API — отдельно (`scripts/history-job.js` + `history-sync.mjs`): тогда его можно прогнать в превью с хранилищем в памяти до первого запуска на раннере. Журнал Actions без входа в GitHub не читается: итог прогона писать туда, где он читается (`status.json` в бакете, аннотации `::notice::`) (2.78).
- R2 отдаёт CORS только `http://localhost:8765` и сайту. Если 8765 занят сервером другой сессии: остановить его автоматический режим не даёт, слушатель на подпути (`http://localhost:8765/wt/`) без прав администратора не стартует («Access denied»), а на 8766 R2 недоступен — ждать, пока порт освободится. Свой сервер на 8765 с открытым входом — копия `serve.ps1` во временной папке с заменой `LOCKED` (2.78). На другом порту без этого бэктест молча идёт с Binance; для сверки истории там — проход `/r2/` в своём сервере (только чтение) и `HS.config({base: location.origin + '/r2'})`. Повторный прогон с теми же датами берёт свечи из памяти вкладки (`histCache`), а не заново — для новой загрузки менять период (аудит C, 2.101).
- `data-api.binance.vision` отвечает с раннеров GitHub (США), `api.binance.com` оттуда не нужен (2.78).
- Деплой функции: MCP `deploy_edge_function` с полными `index.ts`, `../_shared/math.js`, `../_shared/tg.ts`, `verify_jwt: false`. После деплоя `get_edge_function` и diff с репозиторием.
