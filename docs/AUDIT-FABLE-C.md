## Предложения — решает владелец

1. **Вход бота только сразу после закрытия свечи** (к № 2). Сейчас слот, освободившийся посреди свечи, бот занимает сразу — по оценке
   прошлой свечи и текущей цене; бэктест этого не описывает (10–14 % входов на свободных профилях). Вариант: `botTick` разрешает входы
   только первые минуты после закрытия свечи (для 15m / 1h / 4h свеча начинается на кратном времени: `now % tfms`). Тогда бэктест и бот
   совпадают полностью, но бот будет ждать следующего закрытия. За 30 дней входы внутри свечи не были ни заметно хуже, ни лучше
   остальных (−0.05R, +0.09R, −0.34R по трём профилям — выборки по 10–19 сделок), так что это вопрос совпадения с бэктестом, а не
   прибыли. Обратный вариант — учить бэктест входам внутри свечи — требует младших свечей и в разы больше данных.
2. **Не входить по монете без формирующейся свечи** (к № 4): если последняя свеча монеты уже закрыта, а новой нет (торги остановлены,
   монета снята), бот и бэктест сейчас «входят» по последней цене. Вариант: `tradeRow` возвращает `null`, когда `atClose == null`
   и последняя свеча старше одного интервала; в бэктесте — пропуск входа, если у монеты нет следующей свечи, выглядел бы как
   заглядывание вперёд, поэтому там оставить как есть.
3. **Просадка с открытыми позициями** (к № 5): считать «Макс. просадку» бэктеста по балансу с открытыми позициями на закрытии каждой
   свечи. Сейчас разница до 0.5 п. п.; с плечом и большим числом слотов будет больше.
4. **История: число свечей в индексе** (к № 6): ночная задача пишет в индекс число свечей каждого файла и известные пропуски Binance;
   читатель сверяет. Сейчас от «тихо неполного» файла защищает только выборочная ночная сверка (30 файлов за ночь из десятков тысяч).
5. **Тесты.** `tests/_ref/audit.js` (в `.gitignore`) — пересчёт сделок, обрезка свечей, повтор бота, подмены для `history.js`. Если
   нужен в репозитории — перенести в `tests/` отдельным коммитом.
