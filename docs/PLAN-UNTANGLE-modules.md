# Разбиение `index.html` на модули — карта и план

Скилл `untangle-area`, область «структура `index.html`». Владелец 16.11: «да, разбей на модули». Главный мотив — меньше
токенов на чтение и меньше столкновений правок между параллельными сессиями. **Код не тронут: ждёт выбора владельца
(вопросы в конце).** Снимок — HEAD `a7d0807` (2.125 + docs) и рабочая копия 16.11, где другие сессии как раз правят
`index.html` (+341 строка не закоммичено): номера строк ниже приблизительные, ориентир — заголовки разделов
`// ---------- … ----------`.

Решение пересматривает пункт `docs/AUDIT-STATE.md` «Отклонено: … разбиение `index.html` … один файл без сборки выбран
сознательно». Сборки по-прежнему не будет: только нативные ES-модули, которые браузер грузит сам.

## 2. Найденное

**Скрытые связи**
- `UPDATE_FILES` (раздел auto-update) — список файлов, по которым вкладка узнаёт о новой версии, ведётся руками. В нём
  нет `history.js`: правка только `history.js` не перезагружает открытые вкладки, они читают историю старым кодом
  (ошибка, исправить в волне 0). С модулями таких файлов станет 10+, ручной список будет ломаться при каждом новом файле.
- `CHANGELOG` правит каждая сессия в каждом выпуске — это главная точка столкновений в `index.html` (вместе с CSS).
  `CHANGELOG[0].v` — ещё и версия сайта (`#ver`, ключ кэша `learn.js?v=`).
- Порядок старта: `if (AUTH?.rt) EARLY = await syncEarly();` стоит до `let S = … load('sr_settings')`, `favs`, `J`, `BP`,
  `UB`, `ULV`, `EV`, `tf2On` — все 19 чтений хранилища на верхнем уровне должны идти после него. Сейчас это держит
  порядок строк; в модулях это держит только граф импортов (п. 3.2).
- `serve.ps1` отдаёт тип только для `.html` и `.js`: отдельный `.css` без `text/css` локальный Chrome может не применить.

**Связи, которые мешают делить**
- ~30 переменных, которые один раздел объявляет, а другой присваивает (`let`): `J` ← вход, бот на сервере, связка UI,
  события; `jMode` ← 8 разделов; `rows` ← синхронизация, события; `formBase`, `btAll`, `learnPath`, `chartView`, `hoverI/Y`,
  `UB`, `SB_MINE`, `botRegime`, `awaySince`… В ES-модуле импортированная переменная только для чтения: каждое такое место
  нужно переписать (п. 3.1).
- 202 инструкции верхнего уровня, которые выполняются при загрузке (обработчики `$('#x').onclick = …`, `setInterval(scan)`,
  миграции `BP`, `renderChangelog()`, первая проверка версии). При круговых импортах порядок их выполнения задаёт обход
  графа, а не порядок в файле: инструкция, которая при старте трогает `let`/`const` ещё не выполненного модуля, упадёт
  (`ReferenceError`), и сайт не запустится.

**Лишнее и частные случаи** — по этой области не искались (это работа скиллов по каждой области: `PLAN-UNTANGLE-accounts.md`,
`PLAN-UNTANGLE-backtest.md`). Перенос в модули поведения не меняет и мусор не чистит.

## 3. Как делить, не меняя поведения

### 3.1. Общие переменные
- Переменная, которую присваивает только её модуль → `export let`. Остальные видят её живое значение (живая привязка ES),
  код у читающих не меняется.
- Переменная, которую присваивают другие → либо переносится код, который её присваивает, в её модуль (чаще всего так:
  это и есть «то, что меняется вместе, — вместе»), либо модуль-владелец даёт функцию (`setJMode(m)`, `setJ(j)`). Объекта
  «всё состояние в одном» (`st.J`, `st.S`) не делаем: это сотни правок строк ради ничего.
- `S`, `favs`, `J`, `BP` — объекты, их поля и так меняют все (`S.k = …`): это работает и через импорт.

### 3.2. Порядок старта
- Модуль на верхнем уровне только **объявляет** (функции, константы, `let` с чтением своего ключа хранилища). Всё, что
  выполняется при загрузке, — в его `export function start()`.
- `main` импортирует модули и вызывает их `start()` **в сегодняшнем порядке разделов**. Так порядок задан в одном месте,
  а не обходом графа.
- `account.js` делает `await syncEarly()` на своём верхнем уровне. Каждый модуль, который читает хранилище при
  объявлении, импортирует `account.js` (или `core`, который импортирует его) — ожидание верхнего уровня в ES держит всех,
  кто от него зависит. Модуль, который не зависит от `account`, браузер может выполнить раньше — поэтому правило проверяется
  тестом (п. 5): чтение `load('sr_…')` на верхнем уровне есть только в модулях с `account` в цепочке импортов.
- Функции, объявленные через `function`, видны по круговым импортам ещё до выполнения модуля — их порядок не важен.

### 3.3. Файлы, CSP, кэш, автообновление
- Новые файлы того же источника (`app/*.js`, `app.css`): CSP `script-src 'self'` / `style-src 'self'` их уже разрешает,
  `connect-src` не меняется.
- В `<head>` — `<link rel="modulepreload" href="app/….js">` на каждый модуль и `<link rel="stylesheet" href="app.css">`:
  браузер грузит всё параллельно, а не цепочкой импорт за импортом. Таблица стилей в `<head>` блокирует отрисовку —
  вспышки без стилей не будет; ранний скрипт темы остаётся встроенным.
- **Список для автообновления берётся из этих же `<link>`** плюс ленивые `beta.js`, `history.js`, математика:
  `UPDATE_FILES` перестаёт быть ручным списком в коде. Проверка в `tests/smoke.js`: каждый `import` из `app/*.js` есть
  среди `modulepreload` (иначе новый модуль не попадёт в проверку версии).
- Vercel отдаёт статику с `max-age=0, must-revalidate`: при каждой загрузке браузер переспрашивает файл (304 без тела).
  На 10 файлов — 10 коротких запросов, параллельно по HTTP/2; заметно не будет. Окно, когда страница успела взять часть
  старых и часть новых файлов, — секунды во время выкладки; так уже сейчас с `beta.js`, и автообновление перезагрузит
  вкладку.
- `serve.ps1`: тип `text/css` для `.css`.
- `beta.js` по-прежнему получает `window.__sr.kit`; `tests/smoke.js`, `tests/backtest-audit.js` — `window.__sr` (не меняются).

### 3.4. Что остаётся в `index.html`
`<head>`, ранний скрипт темы, разметка (110 КБ) и `<script type="module" src="app/main.js">`. Разметку не трогаем: её
читают по id все модули, перенос в шаблоны — отдельная большая работа без выгоды для токенов.

## 6. Сколько это сэкономит токенов — честно

- Целиком `index.html` (~200 тыс. токенов) и сейчас никто не читает; экономия — не в размере, а в промахах и перечитывании.
- **Перечитывание после чужих правок.** Edit требует свежего чтения, если файл изменился на диске. Сейчас любой выпуск
  любой сессии (CSS, `CHANGELOG`, «Учёба») меняет `index.html`, и все остальные сессии перечитывают куски заново. После
  разбиения сессия бэктеста не видит правок «Учёбы» и дизайна. Это самая большая часть выгоды: по ощущению 20–40 %
  токенов, которые сейчас уходят на `index.html`, в сессиях, идущих параллельно. Измерить заранее нечем.
- **Поиск.** `grep` по слову сейчас возвращает попадания из CSS, разметки и чужих разделов вперемешку; по одному модулю —
  только нужное. Модуль области (бэктест ~14 тыс. токенов, журнал ~11 тыс., «Учёба» ~9 тыс.) можно прочитать целиком
  за один вызов вместо 5–15 кусков с перекрытиями.
- **Столкновения.** Две сессии в разных областях перестают править один файл — меньше «файл изменился», меньше ручного
  слияния, меньше риска закоммитить чужое.
- Не экономит: задачи через весь сайт (новый ключ хранилища, общий токен цвета) и разметку — она остаётся одним куском.
- Волны 0 и 3 дают большую часть выгоды для параллельной работы при малом риске; волны 6–7 — меньше выгоды на единицу риска.

## 7. Где риск
- **Порядок старта (волна 1).** Ошибка = сайт не запускается у всех (белый экран) или стартует на старых значениях
  профиля и отправляет их серверному боту (так было до 2.83). Защита: `start()` по порядку, проверка smoke со входом,
  проверка «без сети на старте».
- **Пропущенное присваивание чужой переменной** — ES выбросит `TypeError: Assignment to constant variable` только когда
  дойдёт до этой строки (например, по редкой кнопке). Защита: скрипт замера из этого плана перед каждой волной находит
  все такие места; плюс клик-пути области.
- **Параллельные сессии.** Перенос блока при чужих незакоммиченных правках в нём = потерянная работа. Нужна «тихая
  минута» на `index.html` на время волны (~час).
- **Привычки и документы.** `CLAUDE.md`, скиллы `click-path-audit` и `untangle-area`, `docs/LESSONS.md` говорят «в
  `index.html`»: обновить в волне 8, до этого — строка в `CLAUDE.md` «где теперь что» после каждой волны.
- Миграций БД нет; функции `bot`/`tg` не затрагиваются.
