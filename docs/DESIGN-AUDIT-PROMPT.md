# Промпт: разбор дизайна, удобства и скорости Sigma Radar

**Как отправлять, чтобы не тратить лишнее:**
- **Новый чат на каждый раунд.** В старом каждый ответ оплачивается заново всеми прошлыми раундами.
- **Сначала проверь версию:**
  `curl -s https://cryptoscreener-topaz.vercel.app/ | grep -m1 -o "v:'[0-9.]*'"`.
  Не изменилась с прошлого раунда — не начинай новый, задай один вопрос про конкретный экран.
- **Узкий снимок.** На repomix.com в поле Include Patterns:
  `index.html,beta.js,supabase/functions/_shared/math.js,CLAUDE.md,docs/AUDIT-STATE.md,docs/DESIGN-RULES.md`.
  Без SQL, сервера, функций бота и прочих `docs`: к дизайну они не относятся и стоят 40–60 тыс. токенов. Если нейросеть сама читает GitHub — снимок не нужен, дай ссылку на репозиторий и этот промпт.
- **Узкий вопрос дешевле полного раунда.** Вместо разбора всего сайта можно спросить про один экран: «журнал на 375 px», «форма бэктеста».

Аудит кода и стратегии — в [AUDIT-CONTINUE.md](AUDIT-CONTINUE.md).

---

Ты — дизайнер интерфейсов и фронтенд-инженер. Найди, что мешает пользователю **Sigma Radar** (сканер Binance с бумажными ботами, бэктестом и Telegram): что тормозит, путает, плохо читается, ломается на телефоне или в светлой теме. Предложи правки в духе проекта.

**Правила ответа (экономия):**
- Преамбула — одна строка: версия снимка и видел ли ты сайт вживую.
- Не предлагай ничего из `docs/AUDIT-STATE.md` — ни сделанного, ни отклонённого без нового довода.
- **До 5 находок**, самые важные первыми, на каждую 3–6 строк. Пять настоящих лучше пятнадцати общих.
- Код — только если неочевиден, 1–5 строк, без целых функций.
- Без пересказа прочитанного, без итоговой таблицы и «итога».

## Шаг 0

1. В `index.html` первая запись `CHANGELOG` должна совпадать с версией в `docs/AUDIT-STATE.md`. Если в снимке версия старше — напиши одну строку «снимок устарел: X вместо Y» и остановись.
2. Прочитай `docs/AUDIT-STATE.md` (что сделано и отклонено), `docs/DESIGN-RULES.md` (правила; ссылайся на §N) и `CLAUDE.md`.

## Как устроен сайт

- `index.html` — разметка, CSS и ES-модуль без сборки, хостинг Vercel. `beta.js` (раздел «Бета») грузится при входе. Общая математика — `supabase/functions/_shared/math.js`.
- **Разделы:**
  - «Рынок» — таблица и график на canvas;
  - «Журнал» — общий бот и «Мой бот», профили, Telegram;
  - «Бэктест»;
  - «Бета» — стаканы и тепловая карта;
  - «Как это работает» и «Что нового».
- Цвета только через токены: `:root` — тёмная тема (основная), `[data-theme=light]` — светлая. Canvas берёт цвета через `pal()`.
- Интерфейс на русском, просто и без жаргона.
- Пользователи — телефоны (часто iPhone, иногда через VPN) и ноутбуки.

## Что разобрать

- первое впечатление на телефоне;
- ощущаемая скорость: функции и цена в мс;
- телефон 375 и 320 px: прокрутка, кнопки меньше 36 px, формы, жесты на графике;
- обе темы: контраст, цвета мимо токенов, рост и падение не только цветом;
- состояния загрузки, пустого экрана и ошибки (`DESIGN-RULES.md` §6);
- понятность текстов;
- доступность: фокус, `aria-label`, клавиатура, `prefers-reduced-motion`;
- единообразие чисел, кнопок и отступов.

## Формат находки

```
[ВЫСОКО|СРЕДНЕ|НИЗКО] Заголовок
Где: файл:строка / селектор / функция · Уверенность: ✅ по коду / ⚠️ проверить на экране / ❓ предположение
Что видит пользователь: устройство, тема, действие → что происходит
Исправление (S/M/L): одна-две фразы или 1–5 строк кода
Как проверить: одна строка
```

В конце — до трёх вопросов владельцу, только если без ответа находку не проверить.
