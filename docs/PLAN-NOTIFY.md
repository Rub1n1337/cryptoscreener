# Уведомления: аудит и план (14 октября 2026)

## 1. Что есть сейчас

В один чат Telegram может приходить пять потоков:

| Поток | Откуда настройки | Монеты | Порог | Нужен «✔ разворот»? |
|---|---|---|---|---|
| Сигналы ≥ 60 (общие правила) | общий бот | его топ | 60 | нет |
| Сделки общего бота | — | — | — | — |
| Сделки моего бота | профиль | профиль | — | — |
| Сигналы профиля | активный профиль (в «авто» он сам меняется по рынку) | профиль или sigTop (новое, v28) | сила профиля, не ниже 40 | **нет** |
| Сигналы «Рынка» | **то, что сейчас открыто на странице «Рынок»** | топ «Рынка» до 400 | порог «Рынка» | **да** |

Данные на 14.10: ботов на сервере 11, Telegram привязан у 2. За минуту считается ~970 анализов монет (бюджет 1800), из них около ⅔ приходится на «Рынок» этих двух пользователей (400 и 250 монет на 1h). Прогон длится ~20 с.

## 2. Найденные проблемы

1. **Бюджет срезал торговлю, а не уведомления** (исправлено в v29). Раньше, когда большой скан «Рынка» у одного бота съедал бюджет, остальные боты пропускали минуту целиком, вместе со входами и выходами.
2. **Скрытая связь с сайтом.** «Рынок» в Telegram берёт настройки с открытой страницы «Рынок». Переключил таймфрейм на сайте, чтобы посмотреть график, — и в Telegram пошли сигналы другого таймфрейма. В Telegram это никак не видно.
3. **Сигнал профиля приходит до подтверждения, а подтверждение не приходит никогда.** Касание запоминается при первом пересечении порога, часто ещё с «⏳ ждём подтверждения». Когда разворот подтверждается (а именно на нём бот входит), второго сообщения нет. Для ручной торговли это самая вредная дыра.
4. **Дубли.** Одно и то же касание BTC может прийти тремя сообщениями: общие правила, профиль, «Рынок».
5. **Пороги не согласованы:** у профиля пол 40, у «Рынка» 40–100, у общего бота 60. Профиль требует только силу, «Рынок» требует ещё и разворот.
6. **Настройки разбросаны:** часть в Telegram (вкл/выкл), часть на сайте (sigTop), часть неявная («Рынок»). Экран «Уведомления» в Telegram не показывает sigTop.
7. **Нет базовых фильтров:** только LONG, тихие часы, ограничение числа сообщений в час.

## 3. Новая модель: правила уведомлений

Вместо пяти жёстких потоков у чата будет список **правил** (до 5). Каждое правило явно хранит:

```
{ name, on,
  source: "profile:<id>" | "custom",   // profile: правила входа берутся из профиля, обновляются вместе с ним
  tf, method, N, k,                    // только для custom
  coins: { top: 20..250 } | { list: [...] },
  minScore, confirmed: true|false,     // присылать только подтверждённый разворот
  sides: "both" | "long" | "short",
  quiet: [fromHour, toHour] | null }
```

- Сделки ботов (общего и своего) остаются отдельными переключателями: это события, а не правила.
- Текущие потоки переводятся в правила один раз: «профиль» → `source: profile`, «Рынок» → `custom` с **замороженными** текущими настройками. Сайт больше не меняет их молча. На странице «Рынок» появится кнопка «Присылать в Telegram с этими настройками» (явное действие).
- **Одно сообщение на касание**, сколько бы правил ни совпало. В сообщении перечислены совпавшие правила и что сделал бот: вошёл / не войдёт и почему / вне его монет.
- **Двухэтапность:** если правило допускает неподтверждённые касания, сообщение потом **редактируется** (а не дублируется): «✔ разворот подтверждён», «🤖 бот вошёл». Для этого храним message_id по ключу «монета:касание».
- Ограничение: не больше N сообщений в час на чат; лишнее собирается в одну сводку.

Редактируются правила на сайте (полная форма). В Telegram у каждого правила есть вкл/выкл, «только LONG» и «тихие часы».

## 4. Ресурсы: как считать дёшево

Принципы (первые два уже в v29):

1. **Торговля первой.** Сначала все боты торгуют, потом сигналы делят остаток бюджета. Пропущенный сигнал не теряется: он запоминается только после отправки и придёт в следующую минуту.
2. **Свечи «только для уведомлений» обновляются реже**: 1h раз в 3 минуты, 4h раз в 5, 1d раз в 15; 5m/15m по-прежнему каждую минуту. Сигнал живёт 5 свечей (5–20 часов на 1h/4h), так что задержка в пару минут ничего не стоит. Анализ необновлённых свечей берётся из прошлого прогона, CPU на них не тратится.
3. **Общий план на прогон** (следующий шаг): собрать все правила всех чатов, сгруппировать по (tf, method, N, k) и посчитать каждую группу один раз на максимальном топе. Дальше каждое правило лишь фильтрует готовый результат по своему топу, порогу и сторонам. Стоимость растёт с числом **разных** настроек, а не с числом пользователей.
4. **Квоты:** не больше 250 монет на правило и 5 правил на чат. Если общий план не помещается в бюджет, правила обслуживаются по кругу (каждое хотя бы раз в 2–3 минуты), торговля не затрагивается.
5. **Запасной вариант на рост:** сканы для уведомлений можно вынести в коллектор на Railway (`server/index.js`), он и так держит свечи. Edge Function тогда оставит себе только торговлю. Нужно, когда разных настроек станет больше ~15.

Оценка для текущей нагрузки: при обновлении 1h раз в 3 минуты «Рынок» 400 + 250 монет даёт в среднем ~220 запросов и анализов в минуту вместо ~650.
