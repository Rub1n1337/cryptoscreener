# Sigma Radar

- Site: single `index.html` (ES module); strategy math in `supabase/functions/_shared/math.js`, shared with the Edge Function `supabase/functions/bot`.
- Candle history: a copy of Binance candles in Cloudflare R2, written nightly by `.github/workflows/history.yml` (`scripts/history-job.js`), read through `history.js` by the backtest and `research/stage05.js` (`docs/PLAN-HISTORY.md`; last run: `status.json` in the bucket). Any new external host the site fetches must be added to the CSP `connect-src` in `index.html`.
- Edge Functions `bot` and `tg` deploy from GitHub Actions on push to `main` (`.github/workflows/deploy-functions.yml`); apply a migration they need before pushing. Run status: `https://api.github.com/repos/Rub1n1337/cryptoscreener/actions/runs?per_page=1`.
- Design/UX rules: follow `docs/DESIGN-RULES.md`; run its checklist (section 12) before every push.
- Changed a button that changes state (bot, journal, backtest, server data)? Run the `click-path-audit` skill (`.claude/skills/`) on that area before pushing.
- The same kind of bug keeps coming back in one area, or a big change is due there? The `untangle-area` skill: map and plan first (`docs/PLAN-UNTANGLE-<area>.md`), code only after the owner picks the fixes.
- Colours only through CSS tokens (`:root` = dark, `:root[data-theme=light]`); canvas code reads them via `pal()` into `PC`.
- Local preview: `serve.ps1` (http://localhost:8765). Pushing to `main` auto-deploys to Vercel and reloads open tabs.
- After changing `math.js`: open `tests/math.html?ref=_ref/math.js` in the preview (the previous copy saved to `tests/_ref/math.js` first); every check must pass. A change to the backtest engine or `botTick`: also run a backtest on 8765 (R2 history) and `tests/backtest-audit.js` in that tab — `recount()` (bad = []), `cut()` (no look-ahead), `replay()` (bot vs backtest); usage at the top of the file.
- A one-line request that can be read two ways, or that states something about the site («раньше было…», «не грузится»): check the claim in the code / git first, and if the meaning is still unclear ask one question before coding.
- Before testing a new trading hypothesis: search the literature first (arXiv q-fin, NBER, BIS, journals via OpenAlex, 15–30 min) and add 1–3 works to `docs/LITERATURE.md` — what was tested, with costs or not, and how their conditions differ from ours (exchanges, coin selection, years, timeframe, costs, long-only or long-short). If there is no serious work, or recent work under similar conditions finds nothing, tell the owner before the run; run only on the owner's decision. Write the run's rules with the works' method in mind and count every combination tried in one shared register of attempts.
- Changelog (`CHANGELOG` in index.html) is for users, in an official, concise style: a 2–5-word title; 1–5 items of one short sentence each («Добавлено…», «Исправлено…», «… стало …»). No mentions of AI, reviews or the development process; no causes, internals, px, «раньше…» stories or numbers that may later change. Entries before 2.40 live in `changelog.js` (loaded when «Что нового» opens); when `CHANGELOG` grows past ~12, move its oldest there.
- `docs/AUDIT-STATE.md` is what other AIs get instead of past rounds: update its version and lists with every release. Their replies are triaged against it first (stale snapshot → one line).
- Problems hit and how they were fixed: `docs/LESSONS.md`. Before work read its short checklist at the top, then grep the section of the area you touch (the whole file is ~36 KB); add a row with every non-trivial fix.
- Before writing what the site does (help, `#legal`, the changelog, `docs/AUDIT-STATE.md`, `docs/LESSONS.md`, a reply to the owner), reopen the code and check it; never from memory, even if it was right an hour ago.
- Do what the task names. Extras you would add (a button, a menu entry, a refactor) go into the report as suggestions, not into the commit; bugs found on the way are fixed and named in the report.

## Working economically
- `index.html` is ~6k lines: find places with grep, read only ranges (sed -n / Read offset+limit). Never read or cat it whole; same for `beta.js`, `math.js`, `bot/index.ts` unless the whole file is the task.
- Text with Cyrillic or other non-ASCII: change it with Edit only, never perl/sed substitutions. A hook (`scripts/check-encoding.sh`, `.claude/settings.json`) checks the changed files after every Edit / Write / Bash / PowerShell call and reports double encoding or invalid UTF-8; fix that before anything else.
- Checks in the preview: `await (await import('/tests/smoke.js?' + Date.now())).run()` at 320 / 375 / desktop (horizontal scroll, overflow, cut text, small touch targets) plus `read_console_messages`; own assertions in the same call; screenshots only for visual changes, at scale ≤ 0.6. A hidden preview pane stops `requestAnimationFrame` — wait with setTimeout in scripts.
- After a push: `bash scripts/after-push.sh <version>` waits for Vercel and the functions deploy and prints one line each.
- One session per plan wave (`docs/PLAN-*.md` keeps the status and is the hand-off); a long session gets compacted and loses detail. One major task per session: when a session has been compacted once, or a new unrelated task comes, write the hand-off (what is done, what is next, open owner decisions) into the plan or `docs/AUDIT-STATE.md` and suggest a fresh session instead of going on.
- Wide read-only searches (many files, naming conventions, «where is X used»): an `Explore` subagent on a cheaper model (`haiku` / `sonnet`); the main model reads its conclusion and does the edits and decisions.
- After changing `math.js`: `tests/math.html?ref=_ref/math.js` (+ `tests/backtest-audit.js` for the engine). After a push: check the served version (Vercel can miss a push).
- CI: `.github/workflows/tests.yml` runs `tests/math.html` and `tests/alerts.html` headless (`tests/ci.mjs`) on every push touching `_shared/` or `tests/`; a red run means a check broke. Its second step (against the previous commit's `math.js`) only reports. It does not replace the preview runs above, and `backtest-audit.js` is not in it (needs R2 history).
